# 排序市场（测试）

市场采用公开 GitHub 静态目录和独立排序清单。玩家浏览、搜索和下载不需要登录；作者使用 GitHub 浏览器授权，在软件内提交审核申请。没有自建发布中转服务器。模组本体仍通过 Steam 订阅下载，不进入市场仓库。

## 范围与发布边界

- 官方市场数据仓库为 `Manhattanca/RimWise-Marketplace`，软件源码和安装包继续使用 `Manhattanca/RimWise`。目录、清单下载、投稿 fork 与 PR 及链接白名单统一使用独立数据仓库。
- 市场入口在主窗口“游戏日志”右侧。首次进入才读取目录；不设置后台轮询。搜索在已下载目录中进行。
- 首版不提供评分、评论、支付或任意文件包。排序清单允许描述资料、工坊编号、明确加载顺序及最多三张 PNG/JPEG 图片。
- 未发布的合集、缺失文件、网络故障和缓存状态需要明确显示，不使用示例数据冒充在线内容。
- 提交申请与上架是两个状态。GitHub 登录不授予作者直接修改官方目录的权限。
- 客户端只对已批准、通过结构校验与散列校验的清单提供下载和应用。

## 作者身份与授权

正式启用登录前，项目维护者需要为 RimWise 注册 GitHub OAuth App，并将回调 URL 配为 `http://127.0.0.1/callback`。登录时软件先在 `127.0.0.1` 绑定系统分配的临时端口，再使用同一路径完成 loopback 回调；不使用固定端口或通配回调。

登录采用授权码 + PKCE (S256)、随机 `state` 和一次性 loopback 回调；用户点击登录后在系统浏览器授权，软件自动接收回调，无需复制验证码。绑定只监听 IPv4 loopback，动态端口由 OS 原子分配，回调校验 Host、路径、state、重复参数、超时及取消状态。

Client ID 是公开应用标识，随软件内置。OAuth Client Secret 由维护者在受控构建时通过进程环境变量 `RimWiseGitHubOAuthClientSecret` 注入，不通过命令行参数、界面、源码或构建日志传递。授权码交换需要该 secret；但客户端二进制中的共享 secret 可被提取，因此不能视为保密凭据，也不应承诺通过客户端加密使其不可见。PKCE 用来降低授权码被截获或替换的风险，不会隐藏共享 secret。普通作者只需在软件内点击 GitHub 登录，不需要填写或注册 OAuth 应用。

未注入 Client Secret 的构建应禁用登录并提示缺少软件登录配置，仍允许保存草稿，不能假装登录成功。用户主动点击登录后才打开系统浏览器；取消、拒绝、超时、窗口关闭及回调校验失败均停止本轮授权。OAuth access token 单独保存在当前 Windows 用户 DPAPI 保护的数据文件中；DPAPI 用于保护用户 token，不用于包装应用共享 secret。

访问令牌只能保存在用户数据中的受 Windows 保护的凭据文件，不能存入排序清单、草稿、普通 JSON、程序目录或诊断导出。下载请求不带发布令牌。注销清除本机保存的授权；撤销 GitHub 端授权通过 GitHub 账户设置完成。

作者提交时核对 GitHub 返回的当前账号；版本清单按作者隔离，不能凭表单中的作者名称冒充他人。提交经个人仓库副本及独立分支发起 PR，审核通过后才进入公开目录。

打开发布窗口不要求手动刷新、后台扫描结束或清除缓存状态。立即捕获当前编辑排序并允许填写／保存草稿；资料未全时可先留空工坊引用。提交时根据打开窗口时的目录设置自动只读核对实际安装来源，补齐工坊编号后再严格验证清单。核对可取消，失败保留草稿，不刷新或替换主编辑器，不向远端提交不完整资料。尚无任何已载入排序时仍需先载入要分享的清单。

## 下载与应用

1. 读取并缓存静态目录；选中条目仅展示目录元数据。点击“下载排序并另存为”或“下载排序并使用”时才获取该版本清单，核对结构、身份和 SHA-256。
2. “下载排序并另存为”保存用户选择的文件，不改变订阅或游戏排序。
3. “下载排序并使用”锁定已审核版本。有绑定合集时批量补订未订阅项，不逐个强制重新订阅。无绑定合集时提示用户是否补全未订阅模组；拒绝补订仍可导入。
4. 等待全部安装或连续 30 秒没有下载活动，右上角提示等待与进度。空闲不代表全部安装；仍缺少模组时提示，排序照常导入保存。
5. 保留作者明确顺序，不补齐依赖、不自动检测或调整排序。声明版本不同仅提示；主界面警告和错误仍正常显示。
6. 保存前重新确认编辑版本、路径、游戏进程和磁盘配置均未变化；使用既有备份、原子写入和撤销记录。
7. 失败或取消保留原排序；已经被 Steam 接受的订阅可能继续下载，应明确提示，不自动取消其他订阅。

市场不保存、分发或固定模组历史二进制版本。作者排序的旧版本不等于可以重现旧版模组组合，不将格式校验和静态依赖检查宣传为游戏运行兼容测试。

## 部署与维护

独立数据仓库 `Manhattanca/RimWise-Marketplace` 已部署匿名目录、图片与投稿校验工作流。工作流只编译基准分支可信工具，把 PR 候选内容作为数据处理；生产数据与目录工作流不随软件源码仓库部署。校验通过后仍需维护者审核，不能将格式校验当作游戏运行验收。

市场页面右上显示共享的 GitHub 登录状态，与发布窗口使用同一会话。“我的排序与草稿”按当前账号列出已发布排序以及本机明确保存的草稿，支持右键修改／删除及双击修改。更新读取已发布的原始排序，沿用原 ID，使用新版本号，可选填更新日志；新发布不展示更新日志。草稿仅点击“保存草稿”才写盘，输入、登录、提交或关闭不自动保存。目录和排序缓存按数据仓库隔离。

投稿最多三张 PNG/JPEG，原图单张不超过 5 MiB。上传前自动压缩，以三张合计 7,000,000 字节为软目标；优先无损，必要时使用有明确像素误差上限的高保真压缩，保留分辨率。达不到目标时保留质量，不因此阻止投稿，不改原图与已保存草稿。

独立审核助手只连接 GitHub，每 1 分钟检查一次，其余时间不轮询 API。查看、登录及审核按需请求。它展示投稿的文本和图片，区分校验等待、失败与缺失，并提供校验网页入口。合并前核对已查看的精确提交、当前主分支及可信工作流记录，合并完成后等待目录生成。图片和文字仍由维护者人工判断。

仓库审核时只接受预期目录内的结构化清单，不执行作者提交的代码、脚本或工作流，不把作者描述渲染为 HTML。公开仓库的作者资料和版本历史会公开，提交前需明确提示。

没有在线目录时，软件继续提供已有排序功能；已有有效缓存可以继续浏览，并显示缓存标记。下载和发布采用用户触发的有限请求，不在软件启动时抢占主窗口呈现。

仅维护项目相关的小型清单，限制内容和自动请求，不把免费仓库当无限网盘；作者需要有权分发所提交资料。
