## 主程序无法打开或导出日志

双击 `Diagnostics/RimWise.Diagnostics.exe`，无需启动 RimWise。工具自动识别用户数据目录，将脱敏诊断 ZIP 保存到桌面并选中文件，可在主程序卡住或退出后运行。请将 ZIP 连同故障时间、操作步骤交给开发者。

包含可用的界面、AI、测试日志及本软件记录的 token 用量；不打包密钥文件、原始配置或内存转储，不自动上传。配置或密钥损坏时生成精简报告并注明缺失。需要已安装 .NET 10 Runtime（安装版已包含运行环境）。

## 0.5.1 更新

修复自动排障遗漏测试辅助 Mod 捕获的实际阻断异常，以及将 Harmony 等共享库调用误关联到无关 Mod 的问题。优先核对阻断游戏流程的调用与本地程序集归属，让试排除更集中于相关 Mod，减少无效重测。

精简 AI 输入中的空关系和重复信息，保留完整排序及必要依赖；调整 DeepSeek 提示词，要求依据已核实的 Mod 标识给出简洁、完整的处理方案。缺少模型样本时统一使用基础 token 预估，实际回报与预估分开记录。

支持读取 Zstandard 压缩的 RWS 存档来导入排序，不修改原存档。修复较小行高下图标显示不全的问题。

拖动预览显示封面、图标与标记，高度跟随列表行高，并增加跟随与轻微倾斜动效。多选时最多显示三张完整卡片，其余显示“以及更多 XX 个 Mod”。常用弹窗与菜单增加短动画，遵循系统动画和高对比度设置。

统一标题栏主题，压缩顶部菜单高度；“开始游戏”移至右下角“保存排序”旁，移除底部“批量标记”按钮，右键标记功能继续保留。

继续提供中文 EXE 安装／更新包和 ZIP 纯净包。本版经过离线回归；具体 Mod 组合仍需实际游戏复测。

## 0.5.0 更新

新增 EXE 安装／更新包，安装器记住上次安装目录，新版本使用独立程序子目录。用户数据保留在原配置位置；卸载程序不删除用户数据。缺少 .NET 10 Desktop Runtime 时，安装器使用随包附带的微软官方安装程序补齐运行环境。

继续提供 ZIP 纯净包。ZIP 用户请关闭软件、清空原程序目录后解压；不要删除另行存放的用户数据。ZIP 需要已安装 .NET 10 Desktop Runtime x64。

本版合并以下 0.4.9 修复及后台更新功能。

## 0.4.9 更新

新增 GitHub 后台更新检测与下载，启动后异步执行，也可在帮助菜单手动检查。检测或下载失败、新版下载并校验完成时在右上角提示，不阻断排序、不自动关闭软件或安装。下载优先选择安装包；ZIP 更新请关闭软件并清空程序目录后解压，保留独立用户数据目录。公开发布之前可能显示暂时无法取得版本。

修复完整自动排序在失败、取消或停止后保存最后顺序时绕过移出确认的问题。开启确认时，保存排序不再默认同意移出临时试排除的 Mod；另行提供“移出并保存”和“不移出，保存排序调整”。试排除中的列表变化仅用于测试，未通过的组合不会宣称排序成功。

改善 DeepSeek 及常见 Chat Completions 兼容服务的请求参数、分段正文、流式结束和用量读取。兼容明确正常结束但未附加尾部标记的完整回复、终帧携带用量与累计用量快照；推理内容不会当作排序方案。适用的官方 DeepSeek 模型降低默认推理强度，为最终方案留出输出空间。

区分输出额度耗尽、回复缺失结束信号和格式错误，记录结束类型及用量便于排查。真正截断、错误或拒绝的回复仍不会执行；缺失有效用量不阻止完整方案，未知用量单独记录。不会自动重复发送同一付费请求。本批使用离线模拟回归，未逐个服务进行真实付费验收；原生 Anthropic Messages、Gemini 和 Responses 接口仍需兼容入口。

## 0.4.8 更新

修复“选择新增 Mod”窗口在深色主题下未选中行出现白底、文字难以辨认的问题；左右列表行背景和边框随主题即时切换。

修复自动测试结束后仍将已退出进程判为游戏运行、阻断下一轮测试与保存的问题；异常退出路径也会等待本轮测试进程结束。启动自动排序时若游戏仍在运行，先提醒保存并询问是否关闭，仅正常关闭玩家确认的游戏。

其他游戏安装留下的旧测试记录不再阻断当前安装；已结束的测试不会因为后来修改了个人排序而无法清理恢复状态。实际运行中的进程仍需核对归属。

合并同一规则在多个模组行重复产生的警告，置顶／置底规则按一项规则统计。保留所有相关模组的提示与定位，不隐藏真正的依赖、兼容或运行错误；诊断导出增加当前问题清单及测试进程记录。

开始前检查 AI 地址与模型，避免未选模型仍先运行游戏。识别 AI 输出额度耗尽与正常回复的区别，新任务增加输出余量；若后续使用新排序复测，按需增加下一次请求额度并继续遵守用户总用量设置。已中断请求不会原样反复重发，半截方案不会执行，用量仍如实记录。

## 0.4.7 更新

修复长 AI 流式回复被软件提前断开、误报“格式不兼容”的问题。逐条处理消息，不再把整次流式传输的重复封装、推理消息和保活消息累计到 1 MB 上限；正常接收最终方案和服务回报的 token 用量。

保留单条消息与回复正文的内存保护，并准确提示大小异常。未完整接收的方案仍不会执行，未知用量仍单独记录；不会自动重发已中断的付费请求。包含此前 0.4.6 的全部修复。

## 0.4.6 更新

新增 Mod 选择窗口不再强制添加模组。未选新增项时可直接点击“整理当前排序并测试”，按完整当前清单执行正常自动排序；不会把本轮已有红字视作新增模式允许的旧错误。

忽略模组元数据指向自身的前置／先后关系，并显示说明；不再因自身关系形成不可解循环。不同 Mod 之间真正的必要前置循环仍会报告。

修复本地程序集分析给出的有效候选位置被二次排序校验误拒绝的问题。候选按实际图约束检查，不再要求重新排序时得到完全相同的平局选择；必要前置、有效先后关系和原有顺序保护继续校验。

冲突处理窗口允许玩家主动移出已标记“必须保留”的 Mod，并以颜色和文字显示覆盖保留保护及连带影响。此选择只作用于本次任务，不删除安装文件、不取消持续颜色保护；自动移除与 AI 仍不能覆盖保留规则。没有可自动移除的选项时返回玩家选择；游戏本体、DLC 及其必要前置继续保护。确认记录贯通测试、恢复、撤销和最终保存。

## 0.4.5 更新

新增 Mod 模式改为“尽量保留现有排序，为新增 Mod 寻找位置”。默认沿用原顺序；必要前置、模组明确先后声明或有效排序规则要求调整时，自动移动相关原有 Mod 并显示原因，不再因为原位置被锁定而直接失败。无关 Mod 尽量保持原顺序，原有 Mod 的移出保护不变。

修复原排序偏好覆盖反向社区规则的问题。原顺序不再冒充强制依赖；真正的必要前置循环仍会报告，缺失前置仍按原流程补齐。不需要 AI 即可完成上述顺序修正。

同步更新 AI 提示词、候选校验、任务恢复和保存链路：没有需求依据的原有 Mod 重排仍会被拒绝，旧测试结果不能用于不同的模组顺序。本版包含此前 0.4.4 的列表动画、行高输入与选中行修复。

## 0.4.4 更新

模组列表滚动滑块在鼠标靠近、离开时平滑加宽与伸长；拖动期间保持尺寸稳定，避免滚动位置跳动。遵循 Windows 的界面动画设置。

行高可直接输入 28–64 的数值，支持回车确认与上下键微调。移除滑杆的白色焦点框，点击轨道和恢复默认时平滑过渡；拖动实时跟随鼠标。修复快速操作或关闭面板时旧动画覆盖新数值的问题。

修复选中模组后内容横移、各列出现重复选中边框的问题，保留日夜主题、颜色标记和多选操作。

## 0.4.3 更新

导入排序或存档时，切换文件类型会切换至对应目录：原版／RimPy XML 优先最近导出目录，存档优先当前游戏的 Saves；JSON／RML 分别记忆导入导出目录。没有可用目录时仍可手动浏览。

修复日间主题下选中模组的文字与背景颜色不协调、文字难以辨认的问题，覆盖多选及窗口失去焦点的状态。

未启用列表左侧新增“行高”按钮，可统一调整模组行高并恢复默认，重启后沿用。封面随较小行高缩放，多行说明保持完整显示。

模组列表竖向滚动滑块增加最小长度；鼠标靠近时加宽并伸长，拖动期间保持放大，方便大量模组时定位和拖动。列表继续使用虚拟化。

## 0.4.2 更新

AI 设置改为服务、密钥和模型三项常用配置，高级选项默认折叠。提供 OpenAI、DeepSeek、硅基流动、Kimi、百炼、智谱、豆包、Gemini、OpenRouter、Groq、xAI，以及本机 Ollama／LM Studio 的 OpenAI 兼容接口预设；中转站与其他服务可选“自定义”。预设不会代选模型，也不代表所有模型均通过真实排序验证。

可粘贴 New API 连接 JSON、常见字段的单组嵌套 JSON、环境变量或中文地址／密钥／模型标签，识别后自动填入草稿。识别过程不联网、不保存粘贴正文；多组或冲突配置提示重新复制，不混用不同服务的密钥。不同网站的私有格式可能需要手填。

“获取模型”查询服务的模型列表，选择后直接使用；列表不支持或不可用时可手动填写。测试连接和获取模型不调用模型生成。密钥显示“已保存”，点击“更换密钥”输入替换值；保留现有用户数据目录和加密存储，覆盖升级无需重新填写。切换地址会清除草稿密钥，避免发送给其他服务。

连接错误按地址／列表不支持、认证、权限、模型或请求参数、限流／额度和服务异常提示。状态码无法唯一确定的问题会保留可能原因，不编造服务端诊断。

修复自动排序窗口顶部设置被截断、次数及 token 控件显示不完整的问题，减少重复标题信息，输入控件成组换行。前两项模式名称改为“不调整现有排序，仅为新增 Mod 寻找位置”和“AI 全部重排序”。保留已有模式设置与排序行为。

新增 Mod 选择窗口采用双栏：左侧未启用，右侧准备测试，支持分别搜索、多选和批量移入／移出。主界面加入排序但尚未保存的 Mod 自动选入右侧，已保存的原有模组保持相对顺序；取消窗口不会改动排序。

在路径设置更换用户数据目录后，下次启动自动迁移配置、加密密钥、任务及历史记录；更换排序日志目录时迁移已导出的本软件日志包。文件复制并校验成功后才清理原文件，遇到占用或中断可继续处理；保留无关文件及无法核实的内容，避免覆盖同名不同内容。迁移期间请关闭其他版本的 RimWise。

## 0.4 更新

新增“为新增 Mod 寻找位置”，位于模式选择第一项。选择要添加的模组后，软件保持原有模组的相对顺序，补齐必要前置，并为新增项寻找位置；先使用本地规则、拓扑及已有程序集分析，遇到需要诊断的问题再调用 AI。

插入模式会先测试原排序作为对照，再测试加入新模组后的组合。如果完整测试证明红字已存在于原排序，且没有新增或加重、没有关联到新增模组，会提示原有问题仍存在并按插入成功保存。无法完成原排序对照或新增需求与固定顺序矛盾时会提示，不能保证任意已有问题的组合均可继续插入。仅有黄字、白字不会因此重复请求 AI。

取消原来的数字分级，原 1／2 级合并为“自动排序”。新增“移出模组前由我确认（保留安装文件）”开关，默认开启；关闭后由软件按已验证结果及保护规则处理移出。必须保留模组始终受保护；插入模式下原有模组也不能被移出。“模组适配（未完成）”继续保留为不可用项。

模式及移出确认设置会记住上次选择；新用户默认选择插入模式。沿用 0.3.9 的每轮回报显示，以及取消、失败、次数或 token 用尽时保留最后测试排序的选择。

## 已有功能

放宽现代游戏配置的版本标记检查：同为包名标识格式的排序不再因为 1.6／1.7 等版本标记不同而直接停止。自动测试按实际安装版本准备相应模组资料，保留当前排序；保存时先备份，再更新过期或缺失的版本标记，保留其他配置内容。旧版文件夹标识迁移、配置结构损坏、外部改动及游戏运行保护仍有效。修复四段游戏版本号无法识别的问题。版本标记兼容不等于模组代码兼容，仍需实际测试。

统一 DeepSeek／GPT 最终回报的 JSON 协议，兼容完整的推理前缀及 JSON 代码围栏，独立推理内容不作为排序动作或公开回报保存。DeepSeek 系列使用兼容的输出上限参数；截断、仅有推理或无效结构仍拒绝，不额外付费重试。此适配不能单独证明已解决服务端 HTTP 400，上下文容量及服务拒绝原因仍需按实际情况核对。

取消自动排序单轮日志大小停止条件。游戏日志、标准输出和错误输出超过原来的采集额度时，测试继续运行并完整采集，结束后按原流程压缩。启动／崩溃日志保留原始内容；真实读写失败仍会报告。

大日志按文件快照完整扫描，首段、中段和末尾的错误均参与判定；界面与 AI 正文只展示摘要，摘要缩短不再被误判为日志采集不完整。本次取消的是单轮测试停止与采集截断，历史日志清理及诊断导出策略沿用现有设置。

修复日志达到采集上限后，已保存的有效错误证据仍被拒绝、导致自动排障中断的问题。已确认停止并完成采集的本轮错误现在可继续用于排序诊断和受保护的临时试排除；日志不完整或地图未验证仍不会判定成功。AI 请求失败时保留用量记录，已有本地依据的试排除仍可继续，正式移出遵循“移出模组前由我确认”设置。

减少发送给 AI 的无关未启用模组关系，以及中文／XML 的重复转义开销；保留完整排序、安装标识和当前必要前置链。新增脱敏的服务错误分类、HTTP 状态及实际加载组件标识，帮助区分请求失败与更新文件混用；不导出密钥或服务端原始错误正文。本版离线验证不代表已修复玩家组合中的全部游戏错误。

日志操作区现在常驻自动排序窗口，不再需要展开。日志保存目录移至“设置 → 路径设置”，提供“打开排序日志文件夹”和“删除全部日志”；更换目录会迁移可确认属于本软件的已导出日志包。

“清理历史日志”保留上次排序证据；“删除全部日志”经确认后也清理最近一次已完成测试的可删除日志，以及当前保存目录中可确认属于本软件的排序 ZIP。运行中和待恢复任务、token 记录、其他文件仍保留；占用、损坏或无法确认归属的 ZIP 跳过。

修复日志清理额度导致自动排序无法继续的问题：额度作为清理目标，不再因恢复记录或无法识别的其他文件超额而阻断测试；实际磁盘读写失败仍会提示。

自动排序窗口的“日志保存”可开关自动导出（默认关闭），或点击“保存上次日志”导出并打开文件夹；目录在“设置 → 路径设置”配置。自动导出在任务成功、失败或取消后执行，保存失败不会改变排序结果。导出包含本次任务日志、界面记录与 token 用量，排除密钥文件并脱敏已知凭据。关闭自动导出仍保留必要运行记录。自动保存目录应位于用户数据目录之外。

修复部分合法模组标识导致 AI 上下文无法发送的问题，保留原始标识；无效的非当前模组元数据会明确记录缺失情况，避免阻断整个任务。当前排序中的无效标识仍会提示处理，不会静默丢失模组。

修复已恢复测试的旧日志无法清理、反复触发空间限制的问题；待恢复任务证据仍受保护。空间不足提示与诊断包增加占用分类，便于区分受保护日志、缓存和其他文件。本次修复不代表游戏中的具体模组兼容性错误已解决。

修复重复安装阻断自动排序的问题。本地与创意工坊副本使用游戏支持的来源标识区分；同来源、同包名的多份安装会在开始前弹窗，显示版本、检查结果和路径，允许选择任意副本或取消。优先推荐文件检查未发现问题的较高 Mod 版本；同版本按工坊编号／文件夹名稳定排列。未填写 Mod 版本时显示未知，不把支持的游戏版本当作 Mod 版本。

选择副本后仍需确认移动方案，未选副本才会移至扫描范围外的同盘备份区，保留内容和原位置记录。此选择影响今后的正常游戏启动；可在“自动排序 → 副本备份”中确认恢复。Steam 重新下载占用原目录时会提示，不覆盖文件。退出或取消选择不会自行移动副本。

使用所选副本的测试未通过时，可提示恢复其他副本供重新选择和复测，仍由用户确认；原任务用量保留，不重放已完成请求，已开启的预算继续扣减。文件检查仅核对当前生效 XML／程序集结构，不保证运行兼容；本版未完成真实游戏中各副本逐一对照验收。

修复自动排序把工坊关联项目误当成必要前置、额外下载整组模组的问题。现在只按已启用模组当前版本 About.xml 声明的必要前置补齐；可选排序关系和工坊关联列表不会自行触发下载或启用。来源有歧义、已知包名不符或版本不匹配时不猜选。

自动排序界面新增“前置与下载原因”，列出每个新增／下载项目由哪些模组要求，并在任务记录中保留原因。旧任务恢复不会重新引入无关前置。此前已订阅的项目不会自动取消订阅，请按实际需要管理。

本版加入本地程序集辅助排序与按需反编译排障。先补齐必要前置并按规则排序，再用明确的程序集提供方关系辅助安排没有先后约束的模组；已有依赖、社区规则及用户规则优先。报错时仅提取可准确定位的少量方法片段供 AI 分析，不执行被分析的 DLL。反编译在本机进行，不需要 Codex；分析失败仍可继续原有日志排障。尚未测得真实任务的 token 节省比例或成功率提升。

修复工坊取消订阅后残留空目录显示为已安装模组的问题，刷新同步更新缓存；当前排序中的缺失项保留供玩家处理。增加缺失模组的 Steam 搜索与工坊页入口，完善批量订阅、逐项失败提示及下载后的增量刷新。Steam 拒绝访问的项目会显示原因，不能绕过项目本身的访问限制。

自动排序成功、失败均有结果弹窗；需要正式移出模组时沿用统一选择窗口。修复未启用的目录链接或失效路径阻断当前排序的问题，同时保留本轮有效模组与测试输出的路径检查。

修复部分 RML 合集无法导入的问题：以主列表为排序依据，允许附加列表顺序不同；按模组标识匹配名称和创意工坊编号，避免下载错配。支持缺少部分附加信息的 RML 文件。关闭软件后完整解压覆盖旧版本即可，沿用原有用户数据和 AI 配置。

自动排序页面提供“清理历史日志”。游戏测试结束后自动回收生成的纹理等缓存，历史日志压缩保存；启动时也会后台整理遗留测试数据。日志保留目标合计 100 MB，超额时清理已结束的旧记录。正在运行的测试、待恢复任务证据等受保护数据可能暂时超过目标，界面会提示；不会为腾出空间删除任务、token 用量记录、密钥或排序备份。

诊断导出支持读取压缩日志并脱敏。覆盖升级沿用用户设置和 AI 配置。

修复自动维护被循环排序建议阻断：循环内互相矛盾的先后建议暂不处理，保留模组并继续游戏测试。必要前置、本体与 DLC 顺序仍须满足，其他规则正常执行；不会改写规则数据库或模组文件。游戏红字仍照常排障，暂缓规则不代表测试成功。

本版修复多选后键盘、右键和拖动操作的一致性。批量加入遇到缺少可用标识的模组时，跳过并说明问题，其余模组正常加入；上下方向键与滚轮保持多选，左右方向键和回车支持整组操作。

新增 ZIP 覆盖升级维护：启动时识别版本变化，校验新版文件，再清理能够核实的旧版废弃资源。保留用户配置及自行添加或修改的文件，只保留最新启动记录和最近一次清理备份。

改进元数据诊断：只有 About.xml.disabled 的模组会显示明确原因，不修改原文件；前置声明中的 Steam 创意工坊协议链接可识别。此类缺少有效元数据的模组仍需使用作者提供的完整版本。

已有“设置 → 导出诊断日志…”，打包界面操作、AI 任务、游戏测试日志及本软件记录的 token 用量；不包含密钥文件、原始设置、存档或模组文件，并对已知密钥和凭据字段脱敏。字段使用简短完整的英文，原始错误保留原文。首次打开自动排序会显示测试提醒，等待 3 秒后确认；确认后升级不重复提示。测试次数与 token 限制可分别开关，新任务默认均关闭，关闭后仍累计记录用量。

保留上一版对模组标识大小写不一致的修复，避免 DLC／前置在正式启动时被误判为未启用。曾用旧版保存排序的玩家，关闭游戏后在新版中点击一次“保存排序”即可修正现有配置；写入前会自动备份。旧版游戏使用的文件夹名称保持原样。

用于管理 RimWorld 模组和排序，可选接入 AI 进行自动排序与游戏测试。当前为公测版。

自动测试通过游戏原生开局页面完成剧本、叙述者、世界、落点与人物配置，再进入地图验证。必要的已安装 DLC 会在启动前按前置声明补回排序；失败后会汇总当轮日志与可关联的崩溃记录。

自动测试完成且没有红字即判定排序成功；黄字、白字保留在日志中，不触发新的 AI 请求或继续排序。成功后统一弹出“自动排序结果”窗口；若无红结果依赖临时移出模组，窗口列出模组并提供“移除模组／不做处理”，两种选择均保存排序。“不做处理”保留这些模组，原有报错可能仍会出现。发生红字时仍结合当轮红字、黄字与上下文排障。插入模式可对照确认原有红字并明确说明；“模组适配（未完成）”暂不可启动。

服务未回报有效 token 用量时，继续处理已经收到的回复，未知部分单独按预估记账；不会计为零，也不会重复发送已完成的请求。实际回报与未知预估共同用于预算控制。

神之手主动输出的“我修复了大部分的报错，但是我保留了一部分……”提示，在内容与调用来源匹配时作为非故障排除；原始日志仍保留，该模组其他错误照常检测。

## 打开和更新

完整解压后双击 **RimWise.exe**。需要 64 位 Windows 和 **.NET 10 Desktop Runtime**，无需安装 Codex、SDK 或 PowerShell。请保留 EXE、DLL、JSON、SteamBridge、Decompiler 和 licenses 的目录结构，支持中文和空格路径。

更新时先关闭 RimWise 和测试任务，将新版完整 ZIP 解压覆盖原程序目录，再启动。带有 `RimWise.package.json` 的新版会校验文件并清理可确认属于旧版的废弃程序资源，保留用户数据和自行添加／修改的文件；文件占用时留待下次启动处理。每个安装位置只保留最新启动记录和最近一次清理备份，不积累版本历史。请保留随包的清单文件；解压不完整时先重新完整覆盖。旧版程序本身不具备这项清理能力。

用户数据默认保存在 `%LOCALAPPDATA%\RimWise\UserData\Data`，包含设置、加密密钥、标记、缓存、备份与任务记录。新版沿用同一数据目录，不用重复填写 AI 配置。首次升级时会从程序旁的旧 Data 或同目录下最近旧版本自动迁移，原数据保留；其他位置的旧数据请先将其 Data 放在新程序旁再首次启动。0.0.55 起允许多个窗口共用数据；0.0.53／0.0.54 仍采用旧版独占锁，首次升级请先保存并关闭这些旧窗口。两个窗口同时修改同一配置时，后保存的窗口会提示重新读取，避免覆盖较新的数据。API 密钥经过 Windows 当前账户加密，换电脑后需要重新填写。请勿分享个人数据目录。

“设置 → 路径设置…”显示用户数据目录。可以选择新的或空的文件夹，保存后自动重启并迁移，原目录保留备份。迁移前请保存排序、结束任务并关闭其他 RimWise 窗口。目标不可用或校验失败时仍使用原目录，不覆盖现有文件。自定义位置记录保存在 `%LOCALAPPDATA%\RimWise\user-data-location.json`。本地模组安全移除仍要求用户数据与本地 Mods 在同一磁盘；需要该功能时可将用户数据目录切换到对应磁盘。

## 模组管理

- 左侧查看模组简介，中间是未启用模组，右侧是当前排序；拖动分隔条调整栏宽。
- 未启用列表按 Enter 或右方向键将所选模组加入排序末尾；已启用列表按 Enter、Delete 或左方向键移出所选模组。上下方向键滚动列表并保持选择。双击和右键也可操作，支持多选、拖动、撤销和取消撤销；移出不删除文件。批量加入遇到缺少可用标识的模组会提示其名称并跳过，其余项目正常加入；必须保留项仍受保护。
- 点击资料区的路径打开对应模组文件夹；创意工坊链接优先在 Steam 客户端打开，未安装 Steam 协议或调用失败时使用浏览器。
- 两份列表可以分别筛选本地／创意工坊来源。未启用列表支持名称、包名、作者、近期新增、近期更新和 Mod 格式排序；中文名称按拼音排列。
- 图标悬停查看含义；黄色表示警告，红色表示错误，悬停或点击底部统计查看原因。
- 两栏行首显示模组提供的封面缩略图，位于来源图标左侧；封面悬停不显示提示，无封面时留空。
- 右键标记提供 16 种颜色，可将某种颜色设为“必须保留”；之后标成该颜色的模组也会受到保护。
- “文件 → 合集管理…”保存和切换命名排序；“清空”移出非官方模组，保留本体及已启用 DLC，不删除安装文件。
- 右键点在多选组内时保留整组，加入、移出、删除本地文件和取消订阅均按所选项处理。右键组外项目则改为单项；多选和 Ctrl+A 不跳转列表位置。
- 本地删除和创意工坊取消订阅会列出本次全部目标供确认；混合来源时分别处理所选本地项或创意工坊项。必须保留项继续受保护，失败逐项列出。本地删除先转入备份，可通过“文件 → 恢复移除的模组…”恢复。

## 路径、保存与导入导出

首次使用优先识别 Steam 游戏及模组路径；可在设置中修改，已保存的自定义路径优先。启动先显示上次缓存，再后台刷新；“刷新”重新读取当前游戏排序与安装。启动时优先核对模组元数据和前置关系，之后补充模组类型与更新时间。核对完成即可开始自动排序，尚未完成的详细读取会暂停；可稍后点击“刷新”补全。

**保存排序**直接写入所选游戏的 ModsConfig.xml，写前自动备份；请先关闭游戏。游戏配置在外部发生变化时会停止覆盖，可从文件菜单预览恢复备份。

可导入原版／RimPy XML、RimSort JSON、RimCrow RML 及可识别的 .rws 存档排序。存档仅读取，不改写。可导出原版／RimPy、RimSort、RimCrow 格式；跨格式转换前会提示可能丢失的字段。颜色信息可在本软件跨电脑读回，第三方工具重新保存后可能不再保留颜色。

从文件菜单选择排序／存档或将单个文件直接拖入主窗口，都会立即替换当前排序，可撤销，不再预览确认。发现缺失模组后立即打开窗口，显示缺失数量及“正在检索”，完成后在同一窗口更新工坊来源。首次目录核对尚未完成时先显示核对状态，检索期间可取消，不会自动订阅。可选择单项、所选或全部订阅下载，也可暂不下载；之后可右键缺失项选择“通过 Steam 订阅下载…”。

所有模组下载均通过已登录的 Steam 订阅，请先配置游戏和工坊目录。工坊来源优先使用文件中编号、已安装模组声明的前置编号，再使用已配置数据库；数据库唯一旧版来源会注明未声明当前版本兼容，不代表可以正常运行。查不到或存在多个来源时，在对应行填写 Steam 工坊链接或编号；本体和 DLC 不能从工坊下载。

“全部下载”先向 Steam 逐项提交所有已确认来源的订阅，再等待安装，不必等待第一个模组下载完成才订阅其余模组。每行显示订阅、下载、等待时间或失败原因；单项失败或超时会继续其余项目。

Steam 确认安装完成后，只读取本轮下载的模组目录，更新其资料并核对包名与实际目录，不扫描整个模组库。当前排序、等待期间的人工调整、撤销记录和其他模组的选择状态保留。可以停止等待；Steam 已接收的订阅可能仍会继续。

## 自动排序

在“设置 → AI 设置…”填写兼容服务的地址、模型和密钥，点击“测试 AI 连接”检查连接。连接测试不生成排序方案，也不提交模组清单；等待 30 秒后仅提示可能超时，可以继续等待或取消。

打开“自动排序”窗口，选择运行模式后，点击 **自动排序并测试**。测试次数与 token 限制可分别开启，默认均关闭；开启后填写上限。开始任务时会保存选择，新任务沿用；恢复旧任务仍沿用该任务原来的限制。关闭限制也会记录 token，未回报的用量单独保留为估算。可选择“为新增 Mod 寻找位置”或“自动排序”；“模组适配（未完成）”暂不可运行。移出确认开关默认开启，关闭后仍保护必须保留项。通常流程如下：

1. 先在本机核对模组声明和工坊数据库中的必要前置，递归补齐并通过 Steam 订阅下载缺失项，再按依赖、社区及用户规则进行拓扑排序；这些步骤不调用 AI，验证通过后才启动游戏。已安装且被明确声明为必要前置的 Mod／DLC 会加入测试排序，启动前可在 AI 窗口查看；仅在可选兼容代码中出现的 DLC 不会据此启用。无法下载的缺失项按移出确认设置处理，保留项及其必要前置继续受保护。
2. 通过 Steam 启动现有游戏，使用独立测试配置依次观察主界面、生成世界并检查派系、加载地图和随机检查殖民者，再确认短时模拟推进。
3. 当轮仍有报错或启动失败时，联合游戏报错、启动／运行日志及可确认属于本轮的崩溃文本报告，向 AI 提供脱敏的首发错误、XML 父定义／工作类、调用栈与最后加载阶段，并只读查找当前模组中的 XML／程序集符号归属。归属是排查线索，不是根因证明；缺失或裁剪的内容明确标记。有效的排序调整会重启复测，初次通过时不请求 AI 生成内容。
4. 若 AI 没有给出有效排序调整，且红字能关联到当前启用模组，可在独立测试排序中临时移出相关模组及连带依赖，再重启验证，无需先证明根因。AI 回复格式无效或未完成时同样检查可试排除的关联项，不执行未通过校验的回复内容，也不自动重发同一次请求。仍有红字时保留累计排除项继续排障，不反复恢复相同失败组合。本体、DLC、必须保留项及其必要前置继续受保护，不删除安装文件。
5. 测试清理会汇总临时排除项并撤回实验性移出。任务尚未通过时，主清单保留已经验证的必要前置和初始规则排序，所有临时排除模组放回；该调整可撤销，不自动写入游戏。取消任务不发布初始调整。试排除后的组合通过时，自动打开处理窗口，按主界面模组行显示整组候选及连带依赖。点击“移除模组”应用并保存这组已测试排序；点击“不做处理”不移出这些模组，仍保存已经完成的排序调整和必要前置；保留全部模组后可能仍有原来的报错。移除不删除模组文件，可撤销；写入前保留备份。两种选择遇到保存失败均保留决定，恢复任务继续保存，无需重复询问或 AI 请求。绿色表示剩余组合实测通过，不能证明每个排除项都有错误。尚未通过验证的候选只保留在排查记录中。没有试排除时，通过后直接应用并保存排序。

准备阶段遇到声明冲突时，窗口同样使用主界面样式的模组列表，支持 Ctrl／Shift 多选，点击“移除”继续，或“不移除”停止本次处理。红底表示尚未打散组合，绿底表示可以继续测试，仍须复测。涉及必须保留项或其必要前置时，以颜色和文字提醒，受保护项不可移出。已开启的次数／token 限制及权限校验继续生效。

必要前置通过已登录的 Steam 订阅和下载；不能可靠识别或下载失败时，会询问是否将缺失项及受影响项移出排序，不猜测工坊项目。受保护项不能移出。取消任务不会自动取消已经完成的订阅。自动测试会临时挂载本软件的固定辅助 Mod，结束后清理，不修改游戏、补丁或玩家模组原件。

每轮先观察主界面，再生成世界并检查派系，然后生成地图、随机选择最多三名殖民者检查人物数据，并确认地图实际推进。出现红字时继续记录并推进测试，到地图验证结束、操作确实无法继续或游戏退出后，才汇总当轮日志交给 AI；成功进入地图仍有红字时继续排障，不能判为无红字通过。地图生成错误框出现，或观察到地图加载场景退出并回到空的主菜单时，结束本轮并收集日志进入排障，不持续等待地图。取消任务或日志超出安全采集上限仍会结束本轮。通过校验的调整从主界面重新测试。测试组件自身故障不会授权随机修改排序。

完整原始日志和崩溃转储留在本机，AI 接收技术事实及经过筛选、脱敏的日志片段。三类来源分别保留空间，优先根错误与日志末尾，最多 48 段、合计 49,152 字符，避免重复刷屏挤掉其他报告。崩溃转储文件不上传、不自动解析；日志尚未生成、无法关联本轮或权限不足时会记录缺失情况。明确的系统环境故障，或既无有效调整也无可试排除的关联模组时，停止并提供本轮日志路径。向其他人求助时请附日志文件和操作过程，不要只提供此窗口截图。

日志中的红字优先于重复黄字，保留错误后的文件信息和异常链。补丁错误明确引用当前启用模组的 XML 时，只读提取对应操作作为诊断线索；文件归属不等于已证实根因。界面列出捕获的具体错误，并区分测试器主动结束与游戏异常退出。每轮 diagnostic-context.json 保存筛选、脱敏后的诊断上下文，便于核对提供给 AI 的证据；未观察到地图信号不会直接判定地图生成失败。

针对 XML 补丁报错，还会只读查找当前排序中修改同一目标的其他补丁及原始定义，连同实际排序位置提供给 AI，用于判断补丁之间是否存在先后顺序要求。按本轮运行版本选择文件，并限制读取范围和大小；条件无法确认或内容被裁剪时明确标注。已安装但未启用的官方内容仅作为定义来源线索，不会因此自动启用 DLC。AI 可以提交排序调整，所有操作仍由本机校验，不提供任意文件读写权限。

缺少 XML 引用或父定义时，即使错误没有文件路径，也会按错误中的类型和标识查找相关定义、引用方及补丁，并沿 ParentName 查找父定义。证据带有来源和排序位置，属于候选线索；不会将同名内容或未启用的官方定义直接当作根因或修复依据。采集有明确限制，不保证覆盖所有自定义加载机制；任何排序修复仍须重新测试。

本轮测试无红字且排序已成功应用后，界面显示“已排序完成”，保存成功时明确提示已自动保存。测试尚未通过、保存失败或玩家选择保留可能冲突的模组时，不显示完成结论；重新激活窗口不会覆盖最终结果。

地图测试会解除本轮测试弹窗带来的暂停，保留日志。仅有黄字不会触发 AI 或继续重测；当轮有红字需要排障时，才将相关黄字与上下文一起分析。

不设置测试总时限。单次游戏启动超过 30 分钟仍未确认进入主界面时，仅提示可能卡死，保留游戏继续等待，可由你取消。等待加载期间不会因此调用 AI、改排序或自动重启；进入主界面也不代表地图测试已经通过。

启动失败涉及电脑／系统配置，或没有可继续验证的有效调整与关联模组时，任务会停止，并显示大致原因、排查建议及本轮日志和启动记录的完整路径，可选中文字复制。请向 Mod 作者或社区提供日志、游戏版本、模组清单和复现步骤，**不要只带着此界面的截图询问他人**。AI 建议不代表已经证明根因；系统建议仅供人工排查，不会自动修改驱动或系统设置。日志可能包含个人路径，分享前请检查隐私。

AI 窗口显示公开回报、请求状态和 token 用量。“用量与余额…”可核对本机记录及受支持服务的近期记录。缺少服务商 usage 时显示未知，不能保证还原全部费用，也不会只按时间把其他软件共用密钥的消耗算给本软件。token 预估仅供参考。

AI 仅获得受控模组及诊断信息；日志在本机筛选并隐藏密钥、路径和地址，日志内容作为不可信数据处理，没有任意文件或终端访问接口。符号归属读取本地 XML 和程序集元数据，不执行其中代码。当前提供自动排序与新增模组插入；模组代码适配尚未开放。游戏与模组仍按普通用户权限运行。

## 中断恢复

软件异常退出或电脑重启后，下次启动会询问是否继续之前的 AI 任务。选择继续会重新检查已保存进度；选择不继续会删除任务恢复内容并停止后续问询。结果未知的远程请求不会自动重发，费用记录独立保留。也可通过“文件 → 恢复任务…”手动处理。

已保存的当轮测试结果和通过校验的 AI 调整可继续使用，恢复不会重置原预算。模组资料或规则变化时会停止使用旧结果；收到但未通过校验的回复不会自动重复请求。

未保存排序有恢复快照；突发断电前最后尚未落盘的操作可能无法恢复。请保留 Data 和备份，不要在任务运行时手动清理。
